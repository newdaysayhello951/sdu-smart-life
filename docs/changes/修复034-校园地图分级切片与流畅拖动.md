# 修复034-校园地图分级切片与流畅拖动

## 问题与处理

上一版按缩放修改整张 8410 × 11890 图片的布局尺寸，导致浏览器反复处理一亿像素原图，操作卡顿。本次将全屏查看器改为 Canvas 视口绘制、五级 WebP 切片，根据缩放和设备像素比只请求可见区域。

- 普通校园地图使用 223034 字节的预览图，不再默认下载 40294821 字节的原始 JPEG；预览放大统一进入全屏查看器。
- 五级共 559 张、约 11 MiB 切片是完整多级资源体积，浏览器按需读取，不是一次全部下载。最高级保留原图像素尺寸，WebP 质量 92。
- 单片不超过 512 × 512，加载并发最多 6，缓存最多 128 张（可见切片优先），Canvas 像素预算约 400 万。
- 连续滚轮和拖动合并到 requestAnimationFrame；交互期间快速采样，停止约 140ms 后恢复高质量采样。仅渲染视野内的建筑按钮。
- 拖动可以从建筑区域开始，按坐标处理单击，键盘仍可选中建筑。保留原图细节、全图、讨论入口和关闭；关闭时销毁绘图组件，释放观察器、动画帧、计时器和切片引用。
- 资源生成脚本：`scripts/build_campus_tiles.py`，运行需要 Pillow，仅处理项目原有静态地图，不涉及用户上传数据。

## 验证

- Vue TypeScript 检查、Vite 生产构建、git diff --check。
- 全部 559 张切片解码完整性和边缘尺寸检查通过。
- 390、1280、1920、3840 宽度设备、六档缩放及四种边缘位置，共 96 组视野覆盖计算通过；这些样本最多同时需要 40 张切片。
- 在现有登录浏览器中观察到新 Canvas 地图与地点面板正常显示。进一步交互验收时检测到用户正在操作，未继续抢占窗口；没有量化浏览器帧率，不能据此承诺固定 FPS。

本次不修改数据库和业务数据。原始地图继续保留为切片生成源。
