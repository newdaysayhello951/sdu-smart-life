# 优化023-实时消息推送与代码文档清理

## 行为
- 私信与通知由3秒/5秒轮询改为登录态SSE推送。每个页面共享一条连接，私信、校园回复及已读变化及时同步。
- 数据库事务提交后才发送更新提示；回滚不产生提示，推送不携带聊天内容。
- 断线自动重连，连接就绪后重新同步数据库中的消息及通知；私聊连续读取50条分页，避免一批消息多于50条时遗漏。
- 消息中心同步时保留已展开通知范围，支持跨标签页已读状态更新。
- 退出、切换账号或会话失效时清理推送连接，防止旧登录态继续接收。

## 清理
- 删除校园页遗留的旧评论状态变量和旧列表样式，清理市场旧卡片、分页样式，以及私聊旧侧栏和个人资料旧折叠面板样式。
- 删除未使用的Pinia依赖和初始化代码，并更新锁文件。
- 修复商品下架错误提示乱码，补齐前端事件监听及提示定时器的卸载清理。
- 更新README：实际页面、实时更新、内存会话、数据存储、旧数据迁移边界及11组回归测试。

## 验证
- 后端2项单元测试：只在事务提交后投递、回滚不投递、身份不匹配拒绝订阅及退出/失效关闭。
- 前端TypeScript与生产构建通过。
- 11组本地API回归通过，新增SSE权限隔离、双向私信、多标签页已读、重连同步、校园回复及退出断流检查。
- 浏览器使用专用测试账号，确认另一会话发送后当前页面无需刷新显示消息及实时连接状态；截图仅保存在本地.tools中。

## 边界
推送连接保存在单个后端实例内，当前没有跨实例广播。登录会话仍保存在内存中；业务数据与上传图片继续保存在MySQL。
